# Code Review: vault-poc

## 1. Общее впечатление

Проект аккуратный, хорошо документированный, сфокусированный на одной задаче — PoC интеграции Spring Cloud Config Server с HashiCorp Vault через composite backend. README на русском языке подробный, содержит архитектурную диаграмму, таблицы, примеры запросов и заметки по безопасности.

---

## 2. Архитектура (оценка: 5/5)

- Composite backend (native + vault) — правильный выбор для разделения секретных и несекретных свойств.
- Native backend имеет высший приоритет — корректно.
- `ConfigTokenProvider` bean — элегантное решение известной проблемы Spring Cloud Config.
- Чёткое разделение ответственности: 2 Java-класса на весь проект.

---

## 3. Безопасность (оценка: 4/5 — для PoC нормально)

- `VaultTokenConfig.java:36` — значение по умолчанию `root-token-poc` захардкожено.
- `docker-compose.yml:8` — `VAULT_DEV_ROOT_TOKEN_ID` открыт в файле.
- Vault работает по HTTP, без TLS.
- README содержит подробный раздел "Безопасность (важно для перехода из PoC в прод)".

**Рекомендация:** Вынести токен Vault в `.env` файл.

---

## 4. Код Java (оценка: 5/5)

### ConfigServerApplication.java
- Минималистично, корректно.

### VaultTokenConfig.java
- JavaDoc отличного качества.
- Использован `@Value` с дефолтом.
- Bean без `@ConditionalOnMissingBean` — корректно: авто-конфигурация Spring (`HttpRequestConfigTokenProvider`) имеет `@ConditionalOnMissingBean`, поэтому наш bean (безусловный) предотвращает создание дефолтного. Добавление `@ConditionalOnMissingBean` на наш bean нарушило бы этот порядок.

**Замечания:**
1. Нет `@ConfigurationProperties` — при расширении лучше вынести.
2. `@Value("${VAULT_TOKEN:root-token-poc}")` использует env var напрямую. Spring рекомендует через property name.
